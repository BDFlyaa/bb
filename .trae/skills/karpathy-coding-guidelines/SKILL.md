# Karpathy 编程准则 (Karpathy-Inspired Coding Guidelines)

本 Skill 旨在优化 AI 编程行为，减少 LLM 在编写代码时常见的误区。这些准则源自 Andrej Karpathy 对 AI 编程缺陷的观察。

## 核心原则

### 1. 先思考，再编码 (Think Before Coding)
不要盲目假设。不要隐藏困惑。明确权衡。
- **明确假设**：如果存在不确定性，请询问用户，而不是猜测。
- **展示多种方案**：当存在多种实现方式时，展示其优缺点，不要私自决定。
- **必要时推辞**：如果用户要求的方案过于复杂，提出更简单的替代方案。
- **困惑时停下**：明确说明不清楚的地方并寻求澄清。

### 2. 简约至上 (Simplicity First)
用最少的代码解决问题。不做任何推测性的开发。
- **不增加额外功能**：只实现用户要求的功能。
- **不为单次使用的代码做抽象**：避免过度设计。
- **不增加未要求的灵活性或配置项**。
- **如果不必要，不编写错误处理逻辑**。
- **如果 50 行能解决，绝不写 200 行**。

### 3. 精准修改 (Surgical Changes)
只修改必须修改的部分。只清理自己造成的“垃圾”。
- **不修改无关代码**：不要“顺便”改进相邻的代码、注释或格式。
- **不重构未损坏的部分**。
- **匹配现有风格**：即使你有更好的写法，也要遵循项目既有风格。
- **清理副作用**：仅移除因你的改动而变得不再使用的 import、变量或函数。不要清理预现的死代码。

### 4. 目标驱动执行 (Goal-Driven Execution)
定义成功标准。循环直到验证通过。
- **将指令转化为可验证的目标**：
  - 错误示例：“添加验证逻辑”
  - 正确示例：“编写针对非法输入的测试，并确保其通过”
- **测试先行**：在修复 Bug 前，先编写能复现该 Bug 的测试。
- **多步骤任务**：先列出简要计划，每一步都包含验证步骤。

## 调用时机
- **开始新任务时**：确保理解需求并定义成功标准。
- **重构代码时**：确保只进行必要的改动并保持简约。
- **遇到模糊需求时**：触发“先思考”原则，主动沟通。
- **任务完成前**：验证是否符合“精准修改”和“简约至上”原则。

## 成功指标
- Diff 中没有不必要的改动。
- 代码结构简单直接。
- 实现前进行了有效的澄清。
- 每一个改动都能追溯到用户的原始请求。
